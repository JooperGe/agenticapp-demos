# Urbanrun Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an independently runnable Flutter + Flame desktop demo in `urbanrun/` with a fixed 45° pseudo-isometric 3×3 city block, keyboard movement, collision, two enterable buildings, and exploration HUD.

**Architecture:** Flutter hosts the desktop window and HUD; Flame renders the game world and forwards input. World logic remains in pure Dart models so projection, movement, collision, scene transitions, and exploration progress can be tested without rendering.

**Tech Stack:** Flutter stable, Dart, Flame, flutter_test.

**Spec:** `docs/superpowers/specs/2026-10-08-urbanrun-design.md`

## Global Constraints

- All implementation files must be inside `urbanrun/`.
- Desktop first; support WASD and arrow keys, Shift for running, E or a clickable prompt for interaction.
- Fixed 45° pseudo-isometric view; no camera rotation in the first version.
- Procedural 2D art only; no external paid asset dependency or direct copying of reference artwork.
- Include a compact 3×3 city block, central park, streets, coffee shop, convenience store, and simple decoration.
- Coffee shop and convenience store must support repeated entry and exit with correct return positions.
- No networking, accounts, real exercise data, complex economy, multiplayer, full NPC AI, or large task system.
- Normalize diagonal movement, clear held input on focus loss, and suppress repeated interaction during scene switching.
- Test projection, movement, collision, interaction range, transitions, and exploration progress.
- README must include dependency versions, desktop run command, controls, and known limitations.
