# Urbanrun 首版设计规格

**日期：** 2026-10-08  
**状态：** 已通过初步设计确认，等待规格审阅  
**范围：** `urbanrun/` 独立 Flutter + Flame 桌面端 demo

## 1. 目标与边界

Urbanrun 是一个受参考图启发的 2D 城市探索 demo。首版目标不是复刻整张宣传图，而是验证一个可以真正行走的城市小街区：玩家从公园出发，沿街探索，进入两个建筑的室内场景，再返回街道完成探索。

首版必须做到：

- 使用 Flutter + Flame 构建，而不是 Unity。
- 首要运行目标为桌面端；支持键盘 `WASD` 和方向键。
- 所有相关文件放在仓库根目录的 `urbanrun/` 文件夹内。
- 使用固定 45° 伪等距镜头表现 3×3 小街区。
- 地图、建筑、树木、车辆、角色和交互标记使用程序化 2D 绘制或简单原创几何图形。
- 至少两个建筑可进入、退出，并且退出后返回对应入口附近。
- 首版不包含联网、真实运动数据、支付、复杂经济系统、多人、完整 NPC AI 或大型任务系统。

程序化绘制可以还原参考图的城市布局、层次和探索氛围，但不会承诺达到参考图的动漫手绘精细度。参考图中的品牌标识、角色、字体和具体美术素材不直接复制。

## 2. 用户流程与可玩闭环

首版的最小可演示流程为：

1. 应用启动后显示街区主场景，玩家出生在中央公园附近。
2. 玩家使用 `WASD` 或方向键在道路、公园和建筑入口区域行走。
3. 玩家靠近咖啡店门口时看到交互提示，按 `E` 或点击提示进入咖啡店室内场景。
4. 玩家在咖啡店室内走动，可以看到出口提示；靠近出口并按 `E` 返回街道。
5. 玩家以同样方式进入便利店并返回。
6. 两个建筑都访问过后，HUD 显示“探索街区 2/2”，并保留已完成状态。

操作约定：

- `W` / `A` / `S` / `D`：移动。
- 方向键：与 WASD 相同。
- `Shift`：跑步，速度为普通移动的固定倍率。
- `E`：在有效交互区域内进入或退出建筑。
- 鼠标点击交互提示：桌面端的备用交互方式。
- 窗口失焦或按键释放后，输入状态必须清空，避免角色持续移动。

不要求首版有战斗、跳跃、背包、存档、任务编辑器、动态天气或昼夜循环。

## 3. 视觉与空间设计

### 3.1 镜头

采用固定 45° 伪等距投影。玩家在逻辑世界中使用二维地面坐标；绘制时通过统一的 `worldToScreen` 转换映射到屏幕。首版不支持旋转镜头，避免地图碰撞、入口朝向和 HUD 方向产生额外复杂度。

镜头跟随玩家平滑移动，并在地图边界内限制摄像机位置。玩家应始终位于画面中心附近，但在地图边缘允许出现更大的可见边界区域。

### 3.2 地图

主场景是紧凑的 3×3 街区，包含：

- 中央公园与出生点。
- 一条横向主街和一条纵向支路，形成十字路口。
- 咖啡店，可进入室内场景。
- 便利店，可进入室内场景。
- 少量住宅/商业建筑作为不可进入的空间边界。
- 树木、路灯、长椅、静态车辆、路缘和斑马线作为环境装饰。

地图必须有明确的可行走区域和阻挡区域。建筑主体、树木大体积和车辆可以产生碰撞；道路、公园路径、入口门前区域必须保持可达。

### 3.3 程序化美术

不依赖外部付费素材包。使用 Flame 的绘制 API 和 Flutter/Flame 基础组件生成以下元素：

- 道路：蓝灰底色、车道线、斑马线和路缘。
- 建筑：暖色矩形/多边形主体、屋顶、窗户、门和招牌色块。
- 公园：草地、路径、圆形花坛、树冠和长椅。
- 角色：原创简化人物几何或小型精灵，包含朝向和行走摆动状态。
- 车辆：静态彩色矩形车体，必要时增加简单车窗和阴影。
- 标记：青蓝色玩家脚下圈、建筑入口提示、任务/探索标记。

颜色应集中在蓝灰道路、暖色建筑、绿色植物和青蓝交互反馈四组主色上。绘制层顺序至少分为地面、阻挡物/建筑、装饰物、角色、交互标记五层，避免角色被地面或不应遮挡的 UI 元素覆盖。

## 4. 技术架构

项目使用 Flutter 应用承载窗口和 HUD，使用 Flame `GameWidget` 承载可交互游戏世界。代码按职责拆分，避免把地图绘制、移动、场景切换和 HUD 状态全部写进一个游戏类。

建议模块边界：

- `UrbanrunGame`：Flame 游戏入口，注册世界组件、摄像机和输入组件。
- `WorldModel`：地图尺寸、街区、障碍物、建筑入口和室内场景定义；不负责绘制。
- `PlayerController`：键盘输入、移动速度、方向、地面碰撞和交互距离判断。
- `IsoProjection`：逻辑地面坐标与屏幕坐标转换，提供可测试的纯函数。
- `CityRenderer` / 场景组件：按绘制层渲染主街区、室内场景和装饰物。
- `BuildingTransition`：进入/退出建筑，保存返回入口，切换当前场景和玩家位置。
- `ExplorationProgress`：记录两个建筑是否访问过，并向 Flutter HUD 暴露只读状态。
- Flutter HUD：角色信息、探索进度、操作提示和小地图；不直接修改游戏世界坐标。

逻辑坐标和显示坐标必须分离。碰撞检测使用逻辑矩形或圆形；只有渲染阶段使用等距转换。这样可以用普通 Dart 单元测试验证移动、边界、投影和入口切换，而不依赖图形渲染。

## 5. 状态与数据流

应用有两个主要状态维度：

1. **当前场景状态**：`street`、`coffeeShop` 或 `convenienceStore`。
2. **探索进度状态**：`coffeeShopVisited`、`convenienceStoreVisited` 两个布尔值。

用户输入进入 Flame 的输入组件，由 `PlayerController` 转换成归一化方向向量，再乘以当前速度和帧间隔。移动前先计算候选位置，与当前场景障碍物测试；发生碰撞时沿可行方向滑动或拒绝该次移动。移动完成后，交互系统检查玩家是否在入口半径内并更新提示状态。

进入建筑时：

- 读取当前入口的室内场景 ID。
- 记录街道返回位置和返回朝向。
- 将当前场景切换到目标室内场景。
- 将玩家放在室内出生点。
- 将对应建筑访问状态置为已访问。

退出建筑时：

- 将场景切回街道。
- 将玩家放置在记录的入口外安全位置。
- 恢复街道摄像机边界和交互检测。

HUD 通过响应式状态或 Flame 游戏暴露的只读状态刷新，不自行维护第二份探索进度。

## 6. 错误处理与边界条件

- 没有交互目标时按 `E` 不产生任何场景变化。
- 进入建筑时必须检查目标场景存在；若配置缺失，保留当前场景并显示短暂错误提示，而不是让玩家进入空场景。
- 出口位置必须经过碰撞检查；若默认出口被阻挡，选择同一入口附近预先配置的安全位置。
- 移动方向每帧归一化，保证斜向移动速度不超过单轴移动速度。
- 场景切换期间暂时忽略重复的 `E` 输入，避免一次按键触发进入后立即退出。
- 窗口失焦时清空按键集合和移动向量。
- 摄像机位置使用地图边界 clamp，不能滚出有效世界区域。
- 资源缺失时使用程序化回退图形，首版不能因单个装饰资源失败而无法启动。

## 7. 测试与验收

### 7.1 单元测试

至少覆盖：

- 等距投影与逆投影的 round-trip 误差在允许浮点误差内。
- 对角线输入归一化后速度与水平输入相同。
- 地图边界阻止玩家越界。
- 建筑阻挡矩形阻止玩家穿墙。
- 入口半径内可交互，半径外不可交互。
- 进入咖啡店后场景和位置正确，并把咖啡店标记为已访问。
- 从室内退出后回到对应街道入口附近。
- 两个建筑访问后探索进度为 `2/2`。
- 场景切换时重复输入不会造成双重切换。

### 7.2 手工桌面验收

实际启动桌面应用并完成以下检查：

1. 启动后能看到 45° 伪等距城市街区和 HUD。
2. 使用 WASD、方向键移动，斜向速度没有明显加快。
3. 玩家无法穿过主要建筑和地图边界。
4. 镜头会跟随玩家，并且不会显示地图外区域。
5. 在咖啡店和便利店入口看到提示，按 `E` 可进出。
6. 室内场景可移动，退出位置正确。
7. 失去窗口焦点后角色不会继续移动。
8. 两个建筑都访问后 HUD 显示完成状态。

## 8. 项目结构约束

所有实现文件必须位于：

```text
urbanrun/
  pubspec.yaml
  lib/
  test/
  assets/        # 首版可为空或只放未来资源
  README.md
```

推荐的 Dart 目录结构为：

```text
urbanrun/lib/
  main.dart
  app.dart
  game/
    urbanrun_game.dart
    model/
      world_model.dart
      scene_model.dart
      exploration_progress.dart
    input/
      player_input.dart
    movement/
      player_controller.dart
      collision.dart
    projection/
      iso_projection.dart
    transitions/
      building_transition.dart
    render/
      city_renderer.dart
      player_renderer.dart
      interaction_renderer.dart
    hud/
      urbanrun_hud.dart
```

实际实现可以合并过小的文件，但必须保持“模型、移动/碰撞、投影、场景切换、绘制、HUD”职责分离。

## 9. 非目标与后续扩展

首版明确不实现：

- 联机或多人同步。
- 真实 GPS、计步或健康数据接入。
- 复杂 NPC 行为树、战斗和追逐系统。
- 账号、云存档、商城和货币。
- 自动生成无限地图。
- 参考图中具体品牌、角色立绘、Logo 或宣传文案的直接复制。

后续可以在首版验收后独立规划：移动端虚拟摇杆、角色动画精灵、任务 NPC、更多可进入建筑、动态车辆、存档和更细腻的原创美术资源。

## 10. 完成定义

当且仅当以下条件全部满足，首版 demo 才算完成：

- `urbanrun/` 是可独立获取依赖并运行的 Flutter 项目。
- 桌面端成功启动并显示程序化 45° 伪等距街区。
- 玩家可在街道和公园区域行走，并受到建筑/边界碰撞限制。
- 咖啡店和便利店均可反复进入和退出。
- 探索进度正确显示并在当前会话内保持。
- 自动化测试覆盖投影、移动、碰撞、交互和场景转换核心规则。
- README 说明依赖版本、桌面运行命令、键盘操作和已知限制。
