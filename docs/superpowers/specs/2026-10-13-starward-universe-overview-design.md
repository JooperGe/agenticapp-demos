# Starward 宇宙全览视图设计规格

**日期：** 2026-10-13
**状态：** 待审阅
**范围：** `starward/lib/ui/galaxy3d/` 的第三个相机档位「寰宇」——从宇宙外部观察整个星表
**前置：** 3D 星图（伪 3D 投影相机 + HYG 星表）已完成；`Universe.universeRadius` 已存在（见 `2026-10-12-starward-voyage-energy-and-drift-design.md` §5.2）

## 1. 目标与边界

在星图页加一个能从**宇宙外部**观察整个数据集的视图档位：一颗半透明的玻璃球，球内是全部真实恒星，飞船的位置和当前航线标在球里。

必须做到：

1. **第三个档位**：星图页侧栏在「总览」「座舱」之外增加「寰宇」档，同页切换，不跳转。
2. **相机在球外**：眼睛位于宇宙边界球之外，目标指向球心（原点＝太阳），可拖动旋转、双指缩放。
3. **镂空玻璃球**：`Universe.universeRadius` 作为球面半径，画成半透明经纬网 + 淡填充；星场夹在前后半球之间，所以恒星读起来在玻璃后面。
4. **飞船位置**：飞船在全览视野下始终可见。
5. **航线**：按真实比例绘制；全览视野下它缩到不可见，因此底栏提供「聚焦航线」按钮一键取景。
6. **读数条**：底栏显示宇宙半径、飞船距球心、飞船距边界。

不做：

- **不做任何点击命中**。寰宇档的 `_onTapUp` 直接返回，不点恒星、不点行星、不出发。`pickPlanet` / `pickStarId` 完全不动。
- 不做独立路由或全屏浮层——是同一个页面的第三个档位。
- 不改 `Universe.universeRadius` 的算法，不改星表，不改存档结构（本规格**零模型变更**）。
- 不在寰宇档绘制行星、宿主星光晕、相位阴影（见 §5.3）。
- 不做多宇宙、不做星系间连线、不做尺度标尺网格。

## 2. 现状（改动前）

- `Camera3D` 有两个档位：`orbit`（总览，绕飞船）与 `cockpit`（座舱，位于飞船）（`camera3d.dart:32`）。
- `Camera3D.eye` 对 orbit 的定义是 `target - forward * distance`（`camera3d.dart:89`），投影用 yaw/pitch + 透视除法（`camera3d.dart:98`）。
- 星图页 `_GalaxyMap3DPageState` 持有唯一一个 `Camera3D`，`_toggleMode` 在 orbit/cockpit 之间二态翻转（`galaxy_map_3d_page.dart:241`）。
- 缩放夹取硬编码为 `70–1800` 世界单位（`galaxy_map_3d_page.dart:105`）。
- 侧栏是两个按钮：二态模式切换 + 居中（`galaxy_map_3d_page.dart:373`）。
- 底栏是传感器范围滑块，范围 `600–5000` 世界单位（`galaxy_map_3d_page.dart:486`）。
- `_drawStarField` 把星等按观测距离重算：`m + 2.5·ln10⁻¹·ln(d_eye²/d_sol²)`（`galaxy3d_painter.dart:187`）。
- `_drawRoute` 按真实比例画航线 + 进度标记（`galaxy3d_painter.dart:398`）。
- 常量：`_worldScale = 12`（`galaxy_map_3d_page.dart:34`），`fovDegrees = 60`。

**已钉住的数字**（`coast_test.dart:157`、`deep_space_start_test.dart:83`）：`universeRadius ≈ 3066 ly`（容差 ±30），太阳位于原点。

## 3. 球心、半径与关键常量

| 量 | 值 | 来源 |
|---|---|---|
| 球心 | 原点 `Vec3(0,0,0)` | HYG 坐标以太阳为原点（`deep_space_start_test.dart:83` 钉住）；`universeRadius` 正是各星到原点的距离分位数 |
| 球半径 `R_ly` | 3066 ly | `Universe.universeRadius` |
| `worldScale` | 12 | 既有常量 |
| 球半径（世界单位）`R_w` | 36 792 | `R_ly × worldScale` |
| 视场角 | 60° | 既有常量 |

**球心必须是原点而不是飞船**。`universeRadius` 的定义就是「到原点距离的 p95」，所以以原点为心画球，球面才真的落在 p95 那层恒星上。若以飞船为心，球面会切过密度完全不同的区域，读数（距球心／距边界）也不再是同一件事。

## 4. 相机 — 复用现有投影，只换目标与距离

### 4.1 眼睛自然落在球外

`Camera3D.eye` 对 orbit 的定义是 `target - forward * distance`。把 `target` 设为原点、`distance` 拉到 `≥ 2R_w`，眼睛就在球外，**投影数学一行不用改**。yaw/pitch 旋转、深度排序、背面剔除全部复用。

所以 `CameraMode.overview` 与 `orbit` 共用同一个 `eye` 公式，区别只在三处：target 的语义、缩放夹取范围、以及 painter 拿到这个模式后走的绘制分支。

```dart
enum CameraMode {
  /// 绕飞船的总览（既有）。
  orbit,
  /// 位于飞船的座舱（既有）。
  cockpit,
  /// 位于宇宙边界球之外的寰宇（新增）。
  overview,
}
```

### 4.2 取景距离的闭式解

球面轮廓在屏幕上的半径**不是** `R·focal/d`。相机在球外时，轮廓是球体的大圆投影，精确解为：

```
rs = focal · R / √(d² − R²)          (d > R)
```

用近似式 `R·focal/d` 在 `d = 2R` 处会少画约 12%，越靠近球面差得越多（`d → R` 时发散）。

`focal = (h/2) / tan(θ/2)`（代码里恒以视口高度推导）。要球刚好内切视口，对高度和宽度各解一次，取较大的 d：

```
d_fit = R · max( 1 / sin(θ/2) ,  √( 1 + h² / (w² · tan²(θ/2)) ) )
```

θ = 60° 时简化为：

```
d_fit = R · max( 2 , √( 1 + 3·(h/w)² ) )
```

- 横屏（w ≥ h）高度约束更紧，`d_fit = 2R` **恰好内切，与视口尺寸无关**。
- 竖屏宽度约束更紧，例如 400×800 → `d_fit = √13·R ≈ 3.606R`。

**默认取景距离** `d_default = 1.15 · d_fit`，留 15% 边距，免得球贴着屏幕边。

**钉进测试的数**（θ=60°、视口 800×600）：`d_fit = 2R = 73 584` 世界单位。

### 4.3 缩放范围与各档语义

| 档位 | 缩放夹取（世界单位） | 说明 |
|---|---|---|
| orbit | 70 – 1800（不变） | 约 6–150 ly |
| cockpit | 改 FOV，不改 distance（不变） | — |
| **overview** | **70 – 5·R_w ≈ 183 960** | 下限与 orbit 相同，所以寰宇档能一路缩到航线尺度 |

**上限必须由 `d_default` 反推，不能拍一个「看起来够大」的数。** `d_default` 随视口变化：横屏 800×600 是 2.3R，竖屏 400×800 是 4.15R。若上限按横屏取 2.6R，竖屏下默认取景距离就会**超过缩放上限**，一进寰宇档相机会被夹到比取景更近的位置，球壳被切掉一截。

取 `5R_w` 是因为它同时高于两种朝向的 `d_default`（2.3R 与 4.15R），并且留了继续往外拉的余量。测试 7 要同时钉住两种朝向。

`居中` 按钮按档分叉：

| 档位 | 居中做什么 |
|---|---|
| orbit | `target = 飞船` |
| cockpit | `eyeOverride = 飞船` |
| **overview** | **`target = 原点`，`distance = d_default`** —— 即「退回全宇宙取景」，也是从「聚焦航线」退回来的路 |

### 4.4 关掉点击

`_onTapUp` 在 `camera.mode == CameraMode.overview` 时直接 `return`。

理由：全览视野下约 **12–16 ly/px**（见 §6.1），13 万颗恒星挤在几百像素的圆盘里，`pickStarId` 的 40 px 阈值会命中一颗**近乎任意**的星。而误触的代价是一次可能烧光能量的航行。所以不做，而不是做得不准。

## 5. 球壳绘制

### 5.1 三段式绘制顺序

这是「镂空」读起来对不对的关键：

```
① 后半球   →  背面经纬网 + 极淡填充
② 球内星场 →  现有的 _drawStarField
③ 前半球   →  正面经纬网 + 更淡的填充
```

星场夹在前后两半之间，恒星于是读起来**在玻璃后面**，而不是贴在一个球上。

前后半球的划分是一个平面：设球心 `C`、相机前向 `f`，

- `dot(P − C, f) < 0` → 远侧（后半球），在①画
- `dot(P − C, f) > 0` → 近侧（前半球），在③画

经纬网：12 条经线 + 6 条纬线，各投影成折线，逐点按上式决定落在①还是③。背面网被星场遮住、正面网压在星场之上——这才是「看穿一个镂空球」的正确观感。顶点数约 672，可忽略。

**填充要极淡**：前半球填充透明度不超过 0.08，否则会把球内星场洗白，全览就成了一颗灰球。

### 5.2 只在球外绘制，靠边时淡出

球壳**只在相机位于球外时绘制**，并在接近球面时按比例淡出：

```
shellFade = clamp( (d/R − 1) / 0.15 , 0 , 1 )
```

- `d ≥ 1.15R` → 完全绘制（默认取景横屏 2.3R、竖屏 4.15R，都在其上）
- `d ≤ R` → 完全不画

这一条同时解决两件事：

1. **正确性**：相机进到球内时，球面不再投影成一个圆，§4.2 的轮廓公式失效。
2. **可用性**：「聚焦航线」会把相机拉到约 880 世界单位（见 §7.2），也就是球内很深。那时球壳彻底不画，画面只剩星场和航线——正是想要的结果。

### 5.3 寰宇档不画的东西

| 元素 | 处理 | 理由 |
|---|---|---|
| 行星 | **全部剔除** | 整个行星集合都在飞船周围约 960 ly 内，全览视野下不足一个像素 |
| 宿主星光晕 | **关掉** | 宿主星是「离飞船最近的那颗」，是局部概念，全览下无意义 |
| 相位阴影 | **关掉** | 依附于行星 |
| 具名亮星标注 | **保留** | 全览下看到天狼星、织女星这些名字，正是这个视图的价值 |
| 航线 | **保留，真实比例** | 见 §7.2 |
| 飞船标记 | **保留** | 需求明确要求 |

### 5.4 球外那 5%

`_drawStarField` 不按半径剔除，所以球壳外的恒星（含 SG-2，中心 3400 ly）会正常画在轮廓环外面。这是对的：`universeRadius` 只约束**漂流**，不约束动力航行，壳外那 5% 是合法目的地。

## 6. 星场 LOD

### 6.1 尺度实测

| 视口 | `d_fit` | 球心处像素尺度 |
|---|---|---|
| 800×600 | 2.000 R = 73 584 | 11.8 ly/px |
| 400×800（手机竖屏） | 3.606 R = 132 672 | 16.0 ly/px |

（球心处 `scale = focal/d`；球面附近因透视会略细。）

于是：

- 一条 1.5 分钟短途航线 ≈ 2.4 ly ≈ **0.15–0.20 px**
- 一条 25 分钟长途航线 ≈ 40 ly ≈ **2.5–3.4 px**

两者都不可见。这是 §7.2 要「聚焦航线」按钮的直接原因。

> 注：早期讨论中曾按 19 ly/px 估算，实测约 12–16 ly/px。结论不变（航线仍不可见），但规格以实测为准。

### 6.2 必须关掉距离衰减

`_drawStarField` 会把星等按观测距离重算（`galaxy3d_painter.dart:187`）：

```
m' = m + 2.5·ln10⁻¹·ln(d_eye² / d_sol²)
```

这个设计是为了「飞船移动时星空跟着变」，在星图尺度上是对的。

**但在寰宇档它会把整个宇宙画成一颗近乎全黑的球。** 默认取景下相机距所有恒星约 73 584 世界单位，而 `d_sol` 从 0 到约 47 000 不等：靠近原点的恒星被压暗约 9 个星等，直接消失；整个银河盘面平均被压暗 1.7 个星等以上。

所以寰宇档必须**关掉距离衰减**，直接用星表里的原始星等（即从太阳看过去的亮度）。这样银河盘面的明暗结构才会正常显示——这正是「根据数据集得来的形状」。

共享的星场绘制函数因此需要一个开关：

```dart
void drawStarField(
  Canvas canvas, {
  required Size size,
  required HygStars field,
  required Camera3D camera,
  required double worldScale,
  required int maxDraw,
  required bool distanceScaled,   // 寰宇档传 false
});
```

### 6.3 绘制上限先不动

`hyg` 5000 / 每个额外星系 5200 保持不变。星表按星等从亮到暗预排序，亮星骨架的形状还在。

这个数是个调参旋钮，不是设计承诺：跑起来看，太稀就调高。注意 `_drawStarField` 的循环在 `drawn >= maxDraw` 时退出，而全览视野下几乎全部恒星都落在屏幕内，所以 `maxDraw` 同时决定**密度和开销**（约等于 maxDraw 次 `drawCircle`）。当前三档合计上限 15 400 次绘制，提高上限要顺带量一下帧率。

## 7. 底栏读数条与聚焦航线

### 7.1 读数条

寰宇档的底栏替掉传感器滑块（`600–5000` 世界单位即 50–416 ly，在全览尺度下无意义）：

```
┌──────────────────────────────────┐
│ ✦ 宇宙全览 · R 3066 ly            │
│ 飞船距球心                1 842 ly │
│ 飞船距边界                1 224 ly │
│ 航线 港湾中枢→织女星        25.4 ly │
│                        [ 聚焦航线 ] │
│ 拖动旋转 · 双指缩放                 │
└──────────────────────────────────┘
```

| 行 | 计算 |
|---|---|
| `R` | `universeRadius` 取整 |
| 飞船距球心 | `playerPosition3D.length`（ly） |
| 飞船距边界 | `R − 距球心`；**为负时显示「壳外 X ly」** |
| 航线 | 仅在 `activeJourney != null` 时出现 |

「壳外」这一档必须处理：飞船确实可能在壳外（SG-2 在 3400 ly，是合法目的地）。

航线行的名字取 `planetById(originPlanetId)?.name` → `planetById(destinationPlanetId)?.name`。`Journey` 存的是行星 id（`journey.dart:50`），所以读数显示行星名。距离 = 两端位置之差的模长。

### 7.2 聚焦航线

按钮把相机取景到刚好框住航线：

```
target   = 航线中点（两端位置的中点）
distance = max( 航线长度_w · focal / (0.6·min(w,h)) , 70 )
```

即让航线占短边的约 60%，并以 orbit 档的最小缩放 70 为下限。

钉进测试：一条 25.4 ly（= 304.8 世界单位）的航线、视口 400×800，`distance ≈ 880` 世界单位。

之后按 `居中` 退回全宇宙取景（§4.3）。

### 7.3 航线按真实比例

沿用现有的 `_drawRoute`（`galaxy3d_painter.dart:398`），几乎不用改：按真实比例画线段 + 进度标记。全览视野下它不可见，缩进去或按「聚焦航线」才看得到。这是选定的取舍——比例永远诚实，靠一个按钮解决可见性。

## 8. 代码结构

`Galaxy3DPainter` 已 528 行，再加球壳和一堆模式分叉会到 650+，而且寰宇档的绘制规则确实不同（+球壳、−距离衰减、−行星、−宿主星光晕）。所以拆开：

| 文件 | 动作 | 说明 |
|---|---|---|
| `lib/ui/galaxy3d/camera3d.dart` | 改 | 加 `CameraMode.overview`；`eye`/`forward`/`project` 不动 |
| `lib/ui/galaxy3d/star_field_painter.dart` | **新建** | 把 `_drawStarField` 的 70 行热循环提成共享函数，加 `distanceScaled` 开关 |
| `lib/ui/galaxy3d/universe_shell.dart` | **新建** | 球壳几何 + 绘制，纯函数，无 Flutter 状态；`shellFade`、轮廓半径、前后半球划分都在这里 |
| `lib/ui/galaxy3d/universe_overview_painter.dart` | **新建** | 寰宇档的绘制编排：后半球 → 星场 → 前半球 → 航线 → 飞船 → 标注 |
| `lib/ui/galaxy3d/galaxy3d_painter.dart` | 改 | 热循环改为调用共享函数；其余不动 |
| `lib/ui/galaxy3d/galaxy_map_3d_page.dart` | 改 | 侧栏四按钮；按 `camera.mode` 选 painter；底栏按档分叉；`_onTapUp` 早退；`居中` 按档分叉 |

抽出热循环是顺带的清理：两个 painter 共用同一份星场实现，不复制那 70 行。这也让 `distanceScaled` 只有一处实现。

`UniverseShell` 是纯函数，只依赖 `Vec3` / `Camera3D` / `Size2`，不依赖任何游戏状态——所以球壳几何可以直接单测，不用建 widget。

## 9. 命名

新档位叫**「寰宇」**，不叫「全览」。

原因：现有的 orbit 档已经占了「总览」（`galaxy_map_3d_page.dart:360` 的副标题「星图 · 总览」，侧栏按钮标签也是「总览」）。「总览」与「全览」同屏出现只差一个偏旁，无法分辨。

| 档位 | 标签 |
|---|---|
| overview | 寰宇 |
| orbit | 总览（不变） |
| cockpit | 座舱（不变） |

顶栏副标题：`星图 · 寰宇` / `星图 · 总览` / `星图 · 座舱视角`。

侧栏由「二态切换 + 居中」改为四按钮竖排，各按钮显示**自己的**档位并高亮当前档（现有的按钮显示的是**目标**档，三档下这个语义会失效）：

```
┌───────┐
│ ✦ 寰宇 │ ← 当前档高亮
├───────┤
│ ◉ 总览 │
├───────┤
│ ⛶ 座舱 │
├───────┤
│ ⊕ 居中 │
└───────┘
```

## 10. 测试策略

沿用 `CLAUDE.md`：TDD 先行、**钉住具体数字**，让「重构不改变行为」可验证。

### 新增

`test/universe_shell_test.dart` — 球壳几何（纯函数，无需 widget）：

1. **轮廓半径用精确公式**：`rs = focal·R/√(d²−R²)`。钉住 `R=36792, d=73584, vp=800×600` → `rs = 300.0`（正好内切，因为 θ=60° 时 `d_fit` 恰好是 `2R`）。同时断言近似式 `R·focal/d` 在同一组输入下给出 `259.8`，比精确值小 13.4%（比值恒为 `√3/2`）——把「不能用近似式」这件事钉死。
2. **前后半球划分**：取球心 `C`、前向 `f`，断言 `dot(P−C,f) < 0` 的点落在后半球集合、`> 0` 的落在前半球，且两者并集覆盖全部顶点。
3. **`shellFade`**：`d = 2.3R` → 1.0；`d = 1.15R` → 1.0；`d = R` → 0.0；`d = 0.5R`（球内）→ 0.0。
4. **球内不画**：`d < R` 时绘制调用数为 0。

`test/overview_camera_test.dart` — 相机与取景：

5. **`d_fit` 闭式解**：`R=36792`、`vp=800×600` → `73 584`；`vp=400×800` → `132 672`（`√13·R`，容差 ±1）。横竖屏都对。
6. **默认取景含边距**：`d_default = 1.15·d_fit`，且此时球面轮廓半径 ≤ 短边一半。
7. **缩放夹取**：overview 档夹到 `[70, 5·R_w]`，且**两种朝向的 `d_default` 都严格小于上限**（横屏 2.3R、竖屏 4.15R，均 < 5R）——这条是防 §4.3 那个越界 bug 的回归测试；orbit 档仍是 `[70, 1800]`（回归）。
8. **`居中` 三档语义**：overview → `target == 原点` 且 `distance == d_default`；orbit → `target == 飞船`；cockpit → `eyeOverride == 飞船`。
9. **`聚焦航线` 取景**：25.4 ly 航线、视口 400×800 → `distance ≈ 880`（容差 ±5），且 `target == 航线中点`。
10. **眼睛在球外**：默认取景下 `(eye − 原点).length > R_w`。

`test/star_field_lod_test.dart` — LOD 开关：

11. **关掉距离衰减**：同一颗星，`distanceScaled: false` 时算出的星等**等于星表原值**；`distanceScaled: true` 时按 `m + 2.5·ln10⁻¹·ln(d_eye²/d_sol²)` 变化。这一条直接钉住「全览不能是黑球」。

## 11. 实施顺序

三个阶段，每阶段独立可验证、不留半成品。

**阶段 1 — 相机档位。** `CameraMode.overview`、`d_fit` / `d_default` 闭式解、缩放夹取分叉、`居中` 三档语义、`_onTapUp` 早退。此时寰宇档已可切换和旋转，只是还看不到球壳（星场已可见）。测试 5–10。

**阶段 2 — 抽热循环 + 关衰减。** 新建 `star_field_painter.dart`，`Galaxy3DPainter` 改为调用它，加 `distanceScaled`；寰宇档传 `false`。此时全览能看到正常的银河盘面。测试 11–12。

**阶段 3 — 球壳 + 底栏。** 新建 `universe_shell.dart` 与 `universe_overview_painter.dart`；侧栏四按钮；底栏读数条与「聚焦航线」。测试 1–4 与 widget 扩展。

阶段 2 依赖阶段 1（要先有档位），阶段 3 依赖阶段 2（球壳要夹在星场前后，得先有共享的星场函数）。阶段 1 单独发布就已经是可用改进。

## 12. 已知取舍

- **不做点击**：全览视野下 12–16 ly/px，命中测试必然不准，而误触代价是一次可能烧光能量的航行。要看某颗星就切回总览档点。这是刻意的取舍，不是遗漏。
- **球壳只在球外绘制**：相机进到球内时球面投影不再是圆，与其做两套几何，不如淡出。副作用是「聚焦航线」时看不到球壳——但那本来也不需要。
- **`universeRadius` 同时是漂流边界和视觉球面**：两者是同一个数，所以球面不是装饰，它就是飞船被关在里面的那个边界。代价是：如果将来为了视觉好看想把球画大一点，就会和游戏规则脱钩，那时应该改成两个量。
- **绘制上限未调**：5000 / 5200 是继承值，密度够不够要跑起来看。`maxDraw` 同时决定密度与开销，调高需量帧率。
- **不画行星**：全览下行星不足一个像素。想看行星得切回总览或座舱。
- **「寰宇」是新增词**：项目此前的词汇是「总览／座舱」。「寰宇」是为了避开「总览／全览」的歧义而引入的，如果日后觉得生硬，可考虑改成「宇宙」或「全景」——但不要改成「全览」。
